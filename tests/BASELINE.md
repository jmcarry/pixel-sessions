# File preview baseline

Run `node --test tests/preview.test.mjs` from the repository root with Node.js 20+ and Python 3 on PATH. The image case uses the macOS version of `sips`. All samples are generated by the suite. It measures helper subprocesses and queue dispatch separately from the Herdr UI.

Before the implementation, the original six cases were run against commit `0228d23`. Markdown/image pane reuse, the 500-selection burst, and the 48 MP image test passed. Generic file routing failed because Files did not open the split. The two generic reader cases failed because a bounded reader was absent.

| Case | Before | After |
| --- | --- | --- |
| 500 queued selections | 0.2 ms, two loads, peak concurrency one | 0.2 ms, two loads, peak concurrency one |
| 8,000 × 6,000 JPEG | 200 ms cold, 46 ms warm, 2,048 × 1,536 output | 237 ms cold, 59 ms warm, same output dimensions |
| 512 MiB sparse log | Bounded preview unavailable | 34 ms, 256 KiB of text, 17.6 MiB helper peak RSS |
| 512 MiB sparse binary | Bounded preview unavailable | 19 ms, 512-byte hex sample, 17.5 MiB helper peak RSS |

These representative measurements come from single local runs. The assertions enforce the payload and concurrency limits, with generous latency and helper memory ceilings. After implementation, an added case checks that plain files use a read-only editor and a failed image load falls back to hex. All seven cases pass.

The native Herdr 0.1.16 checks passed for both changed mods. An isolated window rendered JavaScript with highlighting, a binary hex preview, Markdown, and SVG from local fixtures. Editing the JavaScript fixture refreshed the open pane. Replacing it with a 512 MiB sparse file also rendered the truncated long-line preview. The split and keyboard routing assertions use mocked host commands.

A connected machine passed temporary UTF-8 and binary fixture checks through `hc exec`. Remote rendering in the window was not exercised.
